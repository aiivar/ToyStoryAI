## MODIFIED Requirements

### Requirement: Наблюдаемость этапов
Система ДОЛЖНА (SHALL) логировать каждый этап с именем, кратким входом и выходом, длительностью и, для вызовов LLM, расходом токенов, не записывая в логи секреты. Система ДОЛЖНА (SHALL) поддерживать необязательный асинхронный колбэк прогресса, который вызывается на границе каждого этапа и дожидается завершения до старта следующего этапа, чтобы вызывающая сторона могла сообщить пользователю о ходе работы. Сбой колбэка ДОЛЖЕН (SHALL) логироваться как предупреждение и не прерывать прогон и не подменять его статус.

#### Scenario: Метрики этапа собираются
- **WHEN** этап завершается
- **THEN** в состояние добавляется запись метрик с именем этапа и длительностью, а для LLM-этапа — с числом токенов

#### Scenario: Секреты не попадают в логи
- **WHEN** выполняются любые этапы
- **THEN** в логах отсутствуют токены и ключи

#### Scenario: Колбэк прогресса вызывается на границе этапа
- **WHEN** пайплайн переходит к очередному этапу
- **THEN** колбэк вызывается с именем этапа и дожидается завершения до старта следующего этапа, а без переданного колбэка прогон выполняется без изменений

#### Scenario: Сбой отправителя не прерывает прогон
- **WHEN** колбэк прогресса завершился ошибкой отправки
- **THEN** ошибка попадает в лог как предупреждение, прогон доходит до конца, а его статус определяется этапами, а не колбэком

### Requirement: Запуск из командной строки
Система ДОЛЖНА (SHALL) предоставлять запуск из командной строки с параметрами `theme`, `age`, `moral` и опциональным числом страниц, создающий каталог `output/{timestamp}/` с файлами страниц и файлом `story.json`, содержащим полное состояние прогона. Каталог, заданный самим прогоном, ДОЛЖЕН (SHALL) не перетираться значением из настроек: оркестратор подставляет каталог из настроек только тогда, когда прогон не задал свой, иначе параллельные прогоны писали бы файлы в одно место.

#### Scenario: Каталог результата создаётся
- **WHEN** пользователь запускает CLI с темой, возрастом и моралью
- **THEN** создаётся каталог `output/{timestamp}/` с одним файлом на каждую страницу и файлом `story.json`

#### Scenario: Число страниц по умолчанию
- **WHEN** число страниц не задано
- **THEN** используется значение по умолчанию — шесть страниц

#### Scenario: Некорректный возраст отклоняется
- **WHEN** значение возраста выходит за пределы, заданные настройками
- **THEN** CLI завершается понятной ошибкой, не начиная генерацию

#### Scenario: Некорректное число страниц отклоняется
- **WHEN** число страниц выходит за пределы, заданные настройками
- **THEN** CLI завершается понятной ошибкой, не начиная генерацию (защита от неограниченного расхода на изображения)

#### Scenario: Каталог прогона не перетирается
- **WHEN** прогон запущен с собственным каталогом вывода, отличным от каталога из настроек
- **THEN** оркестратор оставляет каталог прогона, и результаты пишутся в него, а не в каталог из настроек

### Requirement: Централизованные промпты
Все промпты к языковой модели ДОЛЖНЫ (SHALL) храниться в отдельном файле `prompts.py` и не размещаться в модулях этапов или ином коде. Под промптами понимается любой текст, передаваемый языковой модели, включая корректирующий промпт LLM-клиента и формулировки проблем, которые валидаторы подставляют в перезапросы; модули вне `prompts.py` могут лишь собирать шаблон с данными. Каждый промпт, запрашивающий JSON, ДОЛЖЕН (SHALL) сопровождаться явной инструкцией о форме ответа, которая перечисляет верхнеуровневые поля, запрещает служебные ключи самой JSON-схемы и показывает короткий пример-заготовку; сама инструкция и пример ДОЛЖНЫ (SHALL) выводиться из модели данных этапа, чтобы добавление поля не оставляло инструкцию врать.

#### Scenario: Промпты вынесены отдельно
- **WHEN** требуется изменить формулировку промпта этапа
- **THEN** изменение вносится только в `prompts.py`, без правок кода этапа

#### Scenario: Корректирующий промпт клиента тоже в `prompts.py`
- **WHEN** LLM-клиент повторяет запрос после ошибки схемы
- **THEN** текст повторного запроса берётся из шаблона в `prompts.py`, а не пишется в коде клиента

#### Scenario: Текст промпта не появляется в другом модуле
- **WHEN** проверяется соответствие требованию
- **THEN** ни один модуль пайплайна, кроме `prompts.py`, не собирает текст обращения к языковой модели из строковых литералов

#### Scenario: Служебные ключи схемы запрещены
- **WHEN** промпт этапа запрашивает JSON по схеме
- **THEN** следом за схемой идёт инструкция, перечисляющая верхние уровни ответа, запрещающая использовать служебные ключи схемы (`description`, `properties`, `required`, `type`, `title`) как данные и показывающая пример-заготовку формы

#### Scenario: Запрет не противоречит модели
- **WHEN** модель данных этапа сама объявляет поле с именем служебного ключа
- **THEN** этот ключ исключается из списка запрещённых, чтобы инструкция не требовала и не запрещала одно и то же

#### Scenario: Форма ответа выводится из модели данных
- **WHEN** в модель данных этапа добавлено поле
- **THEN** перечень верхнеуровневых полей и пример-заготовка обновляются сами, без ручной правки текста промпта
