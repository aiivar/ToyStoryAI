## MODIFIED Requirements

### Requirement: Реестр сущностей (экстрактор)
Этап извлечения ДОЛЖЕН (SHALL) принимать все страницы сказки и описание игрушки, полученное по присланному фото, и возвращать реестр: `characters` с полями `name`, `appearance`, `clothing`, `distinguishing_features`; `locations` с `name` и `description`; `key_objects` с `name` и `description`; и единый `art_style` для всей сказки. Описания героя ДОЛЖНЫ (SHALL) опираться на переданное описание игрушки, а не выдумываться моделью: вид, цвет, наряд и отличительные детали берутся из распознанного описания, чтобы текст и иллюстрации описывали одну и ту же игрушку.

#### Scenario: Реестр извлекается из страниц
- **WHEN** экстрактор получает все страницы сказки
- **THEN** результат содержит персонажей, локации, ключевые объекты и единый стиль иллюстраций

#### Scenario: Описания пригодны для повторного использования
- **WHEN** формируются описания персонажей
- **THEN** они конкретны и визуальны и допускают дословный повтор на каждой странице

#### Scenario: Стиль задан один раз
- **WHEN** формируется `art_style`
- **THEN** он единый для всей сказки

#### Scenario: Описание героя не выдумывается
- **WHEN** в прогоне есть описание игрушки по фото
- **THEN** промпт экстрактора содержит это описание и прямой запрет выдумывать внешность героя, а поля `appearance`, `clothing` и `distinguishing_features` опираются на него

#### Scenario: Описание игрушки недоступно
- **WHEN** прогон идёт без фото игрушки, то есть описание не передано
- **THEN** в промпте экстрактора вместо описания стоит явная заглушка с просьбой выбрать облик героя по тексту сказки, а не пустой блок и не строка `None`
