## Purpose

Постоянное сохранение каждой генерации, выполняемой ботом, чтобы результаты можно было восстановить, проверить и использовать для контроля лимитов на пользователя.

## ADDED Requirements

### Requirement: Содержимое записи о генерации
Система ДОЛЖНА (SHALL) сохранять запись для каждой генерации, содержащую идентификатор пользователя, отметку времени, тип генерации (сказка или видео), статус, ссылки на файлы или URL созданных артефактов и идентификатор запроса к видеопровайдеру, когда он применим.

#### Scenario: Запись о сказке сохранена
- **WHEN** сгенерирована сказка
- **THEN** система сохраняет запись с идентификатором пользователя, временем, типом «сказка», статусом и ссылкой на содержимое сказки

#### Scenario: Запись о видео сохранена с идентификатором запроса
- **WHEN** запускается генерация видео
- **THEN** система сохраняет запись с идентификатором пользователя, временем, типом «видео», статусом и идентификатором запроса провайдера

#### Scenario: Запись о видео обновлена результатом
- **WHEN** генерация видео достигает терминального состояния
- **THEN** система обновляет статус своей записи и сохраняет ссылку на файл или URL готового видео

### Requirement: Жизненный цикл статуса
Система ДОЛЖНА (SHALL) отслеживать каждую запись о генерации через статусы, различающие выполнение, успешное завершение и неудачу.

#### Scenario: Статус выполнения
- **WHEN** генерация началась, но не завершилась
- **THEN** статус её записи отражает, что она выполняется

#### Scenario: Статус успеха
- **WHEN** генерация успешно создала свой артефакт
- **THEN** статус её записи отражает успех

#### Scenario: Статус ошибки с причиной
- **WHEN** генерация падает
- **THEN** статус её записи отражает ошибку и сохраняет признак ошибки для диагностики

### Requirement: Получение истории по пользователю
Система ДОЛЖНА (SHALL) уметь получать записи о генерациях пользователя, чтобы бот мог определить его предыдущее использование.

#### Scenario: История запрашивается для пользователя
- **WHEN** системе нужны прошлые генерации пользователя
- **THEN** она возвращает записи этого пользователя, упорядоченные от новых к старым

#### Scenario: История изолирована по пользователю
- **WHEN** история запрашивается для одного пользователя
- **THEN** записи, принадлежащие другим пользователям, не возвращаются
