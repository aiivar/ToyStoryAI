## Why

Существующий ToyStoryAI выдаёт одну сказку на 150–300 слов и короткое видео. Для сценария «сказка-книжка с иллюстрациями» этого недостаточно: нужна многостраничная история, где каждая страница — текст из 2–3 предложений и отдельный слайд, а главный герой выглядит одинаково на всех слайдах. Ключевая продуктовая ценность — визуальная согласованность персонажа между страницами и соответствие сюжета канонам детского повествования (завязка → нарастание → кульминация → развязка).

Такую задачу нельзя решить одним вызовом LLM: она распадается на планирование, написание, извлечение устойчивых описаний героев, раскадровку и проверку качества. Поэтому нужен явный, наблюдаемый пайплайн, где каждый этап решает одну задачу, а согласованность персонажа обеспечивается общим «якорем» описания, повторяемым в каждом промпте изображения.

Существующий бот при этом не затрагивается: это новая автономная capability для CLI и библиотеки.

## What Changes

- Новый подпакет `app/story_pipeline/` внутри ToyStoryAI: восемь этапов (планировщик → сценарист → экстрактор сущностей → раскадровщик → сборщик промптов → генератор изображений → судья → ревизор) и оркестратор явного графа состояний на asyncio.
- Новый единый объект состояния `StoryState`, протаскиваемый между этапами и полностью сериализуемый в `story.json`.
- Новый `StorySettings` на `pydantic-settings` — отдельный от бота, чтобы CLI не требовал `MAX_BOT_TOKEN`; переиспользует существующие `DEEPSEEK_*`.
- Все промпты к LLM вынесены в отдельный файл `prompts.py`; схема JSON генерируется из pydantic-моделей, а не дублируется в тексте промпта.
- Чистый сборщик промптов изображений (без LLM) по формуле с дословным «якорем» описания персонажа; локации и объекты обогащаются короткими описаниями из реестра.
- Генерация изображений через настраиваемого провайдера: `GeminiImageProvider` (Nano Banana) и `MockImageProvider`, автоматически включаемый при пустом `GEMINI_API_KEY`.
- Единый «character sheet» как reference-изображение для всех страниц — гарантия узнаваемости героя.
- LLM-судья с `temperature=0` (три критерия, вердикт `{passed, issues, problem_pages}`) и ревизор, правящий только проблемные страницы, с лимитом в 2 цикла и пометкой `needs_review`.
- CLI: `theme`, `age`, `moral`, `--pages`, создающий `output/{timestamp}/` с `page_1.png … page_N.png` и `story.json`.
- Внешние API: DeepSeek (переиспользуется для всех текстовых этапов: планировщик, сценарист, экстрактор, раскадровщик, судья, ревизор) и Google Gemini image для иллюстраций.

Вне рамок: UI (веб/мобильный), платежи, аутентификация, оптимизация под продакшн-нагрузку, интеграция пайплайна в диалог бота.

## Capabilities

### New Capabilities
- `story-orchestration`: единый `StoryState`, явный граф состояний, логирование этапов (вход/выход/время/токены), цикл ревизии и CLI-запуск с выдачей `output/{timestamp}/`.
- `story-text-generation`: планировщик (бриф), сценарист (страницы), экстрактор сущностей (реестр персонажей/локаций/объектов, `art_style`) и раскадровщик (сцены), с валидацией ссылок на реестр.
- `story-illustration`: чистый сборщик промптов, единый character sheet как reference, генерация PNG по странице, ретраи и сохранение seed, mock-провайдер.
- `story-quality-review`: LLM-судья (`temperature=0`) по трём критериям и ревизор, правящий только проблемные страницы, с лимитом ревизий и пометкой `needs_review`.

## Impact

- **Новый код**: `app/story_pipeline/` (`models.py`, `prompts.py`, `pipeline.py`, `cli.py`, `settings.py`, `stages/`, `providers/`) и `tests/story_pipeline/`.
- **Новые внешние зависимости**: нет — используются уже зафиксированные `httpx`, `tenacity`, `pydantic`, `pydantic-settings`, `loguru`, `pytest`, `pytest-asyncio`.
- **Внешние API**: DeepSeek (`api.deepseek.com`, переиспользуется) и Google Gemini image (иллюстрации).
- **Конфигурация**: новые переменные `GEMINI_API_KEY`, `GEMINI_BASE_URL`, `GEMINI_MODEL`, `GEMINI_TIMEOUT`, `STORY_*` (число страниц по умолчанию, лимит ревизий, диапазон возраста, каталог вывода); существующие `DEEPSEEK_*` переиспользуются. Обновляются `.env.example` и таблица переменных в `README.md`.
- **Рабочие артефакты**: каталог `output/` с результатами прогонов (добавляется в `.gitignore`).
- **Стоимость**: каждый прогон — несколько текстовых вызовов DeepSeek и `N + 1` вызовов генерации изображений (character sheet + по странице); при пустом `GEMINI_API_KEY` изображения мокаются и расходов нет.
- **Существующее поведение**: бот MAX, его сервисы, БД и квота не изменяются.
