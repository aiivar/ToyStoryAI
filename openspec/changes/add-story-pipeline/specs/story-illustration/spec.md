## Purpose

Визуальная часть пайплайна: детерминированная сборка промптов изображений без участия языковой модели, единый anchor-персонаж, reference-изображение для всех страниц и генерация PNG через заменяемый провайдер с устойчивостью к сбоям.

## ADDED Requirements

### Requirement: Сборщик промптов — чистая функция
Сборка промпта изображения ДОЛЖНА (SHALL) быть детерминированной функцией без обращения к языковой модели и без ввода-вывода, собирающей строку из единого стиля, полных описаний персонажей сцены, описания сцены, локации и объектов и завершающейся требованием согласованности персонажа и стиля детской книжки. Канонический формат строки: `{art_style}. {полные описания персонажей через пробел}. {scene_description}. Location: {локация}. Objects: {объекты через запятую}. Consistent character design across all pages, children's book illustration.`

#### Scenario: Формула промпта соблюдена
- **WHEN** собирается промпт для сцены
- **THEN** результат содержит единый стиль, описания персонажей, описание сцены, локацию, объекты и фразу о согласованном дизайне персонажа и детской книжной иллюстрации

#### Scenario: Языковая модель не используется
- **WHEN** собирается промпт изображения
- **THEN** никакие обращения к языковой модели не выполняются

#### Scenario: Сцена без персонажей
- **WHEN** в сцене нет персонажей
- **THEN** промпт формируется корректно с пустым перечислением персонажей

### Requirement: Полное описание персонажа как якорь
Промпт изображения ДОЛЖЕН (SHALL) включать полное описание персонажа из реестра сущностей дословно, единообразно на всех страницах, как основу визуальной узнаваемости. Полное описание (`full_desc`) — вычисляемое поле персонажа, собираемое из `appearance`, `clothing` и `distinguishing_features` в фиксированном порядке, а не отдельно хранимое значение.

#### Scenario: Полное описание вычисляется детерминированно
- **WHEN** формируется полное описание персонажа
- **THEN** оно собирается из полей внешности, одежды и отличительных черт в фиксированном порядке и воспроизводимо символ в символ

#### Scenario: Описание повторяется дословно
- **WHEN** один и тот же персонаж присутствует на нескольких страницах
- **THEN** его полное описание входит в промпт каждой страницы без изменений

### Requirement: Обогащение локаций и объектов
Промпт изображения ДОЛЖЕН (SHALL) подставлять локацию и объекты с их короткими описаниями из реестра, если описания доступны, и деградировать до чистого имени, если описания нет.

#### Scenario: Локация с описанием
- **WHEN** у локации есть описание в реестре
- **THEN** в промпт попадают и имя, и описание локации

#### Scenario: Описание отсутствует
- **WHEN** у локации или объекта нет описания
- **THEN** в промпт попадает только имя, без ошибки

### Requirement: Единый reference-персонаж для всех страниц
Система ДОЛЖНА (SHALL) до генерации страниц создать одно reference-изображение персонажей (character sheet) по реестру сущностей и передавать его как reference при генерации каждой страницы.

#### Scenario: Reference создаётся первым
- **WHEN** начинается генерация изображений
- **THEN** сначала создаётся character sheet, а затем страницы

#### Scenario: Страницы используют reference
- **WHEN** генерируется страница
- **THEN** в вызов провайдера передаётся reference-изображение character sheet

### Requirement: Генерация PNG по странице
Система ДОЛЖНА (SHALL) сохранять по одному PNG-файлу на страницу с именем вида `page_N.png` и записывать для каждого изображения использованный seed, если провайдер его вернул.

#### Scenario: Файл на каждую страницу
- **WHEN** генерация изображений завершена успешно
- **THEN** для каждой страницы существует файл PNG, а в состоянии сохранены путь и seed

#### Scenario: Seed сохраняется для воспроизводимости
- **WHEN** провайдер поддерживает seed и вернул его
- **THEN** значение seed сохраняется в состоянии прогона

### Requirement: Устойчивость генерации изображений
Система ДОЛЖНА (SHALL) повторять временно неуспешные вызовы генерации изображения до трёх раз и при постоянной ошибке не прерывать весь прогон: продолжать оставшиеся страницы и помечать результат как `needs_review`.

#### Scenario: Временный сбой повторяется
- **WHEN** вызов генерации изображения падает с временной ошибкой
- **THEN** система повторяет попытку до трёх раз

#### Scenario: Страница не удалась после повторов
- **WHEN** все попытки для страницы не удались
- **THEN** оставшиеся страницы генерируются, а прогон завершается со статусом `needs_review`

#### Scenario: Постоянная ошибка конфигурации
- **WHEN** провайдер отклоняет учётные данные
- **THEN** прогон завершается понятной ошибкой, не расходуя попытки на нетранзиентную ошибку

### Requirement: Заменяемый провайдер изображений
Система ДОЛЖНА (SHALL) обращаться к генерации изображений через протокол провайдера и использовать mock-провайдер при пустом ключе, не выполняя реальных вызовов.

#### Scenario: Mock без ключа
- **WHEN** ключ генерации изображений пуст
- **THEN** используется mock-провайдер и реальные HTTP-вызовы не выполняются

#### Scenario: Детерминированный mock
- **WHEN** mock-провайдер вызывается дважды с одинаковым seed
- **THEN** результат детерминирован
