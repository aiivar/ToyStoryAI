## Purpose

Генерация иллюстраций сказки через RouterAI: OpenAI-совместимый вызов с поддержкой reference-изображений, seed и соотношения сторон. Провайдер скрыт за протоколом, умеет работать без ключа (mock) и переживает временные сбои.

## ADDED Requirements

### Requirement: Вызов RouterAI за протоколом провайдера
Система ДОЛЖНА (SHALL) генерировать изображения через реализацию протокола `ImageProvider`, которая отправляет POST на `{ROUTERAI_BASE_URL}/images` с заголовком `Authorization: Bearer <ROUTERAI_API_KEY>` и телом, содержащим `model`, `prompt`, `n=1`, `seed`, `aspect_ratio` и `input_references`.

#### Scenario: Запрос сформирован по документации RouterAI
- **WHEN** генерируется изображение с одной картинкой-референсом
- **THEN** отправлен POST на `/images` с Bearer-аутентификацией, а тело содержит модель, промпт, `n=1`, `seed`, `aspect_ratio` и ровно одну ссылку в `input_references`

#### Scenario: Ключ не подставляется в тело или URL
- **WHEN** формируется запрос
- **THEN** ключ присутствует только в заголовке `Authorization` и отсутствует в URL и теле

### Requirement: Reference-изображения как data URI
Провайдер ДОЛЖЕН (SHALL) передавать референсы в виде `data:image/…;base64,…`, определяя MIME-тип по содержимому байтов, и ДОЛЖЕН (SHALL) поддерживать JPEG, PNG и WebP.

#### Scenario: MIME-тип определён по содержимому
- **WHEN** в референс переданы байты JPEG, PNG или WebP
- **THEN** data URI содержит соответствующий MIME-тип, определённый по сигнатуре файла, а не по расширению

#### Scenario: Референс не задан
- **WHEN** изображение генерируется без референсов
- **THEN** `input_references` не передаётся, запрос уходит без референсов

#### Scenario: Поддерживается несколько референсов
- **WHEN** передано несколько референсов
- **THEN** в `input_references` присутствует по ссылке на каждый байтовый референс

### Requirement: Seed и соотношение сторон
Провайдер ДОЛЖЕН (SHALL) передавать `seed` в теле запроса, если он задан, и ДОЛЖЕН (SHALL) принимать соотношение сторон параметром, чтобы повторный вызов с тем же seed давал тот же результат. Соотношение сторон ДОЛЖНО (SHALL) проверяться по списку поддерживаемых значений до начала генерации, а нераспознанное значение — отклоняться.

#### Scenario: Seed доходит до провайдера
- **WHEN** изображение генерируется с заданным seed
- **THEN** значение seed присутствует в теле запроса

#### Scenario: Seed не задан
- **WHEN** seed не передан
- **THEN** поле seed в теле запроса отсутствует, а результат не содержит выдуманного значения

#### Scenario: Соотношение сторон подставляется
- **WHEN** генерируется страница с соотношением сторон из настроек
- **THEN** в теле запроса указано это соотношение

### Requirement: Формат возвращённого изображения
Провайдер ДОЛЖЕН (SHALL) возвращать вместе с байтами изображения тип файла, полученный от провайдера, и ДОЛЖЕН (SHALL) не выполнять конвертацию: расширение сохраняемого файла и вложения определяется этим типом, а не предположением о PNG.

#### Scenario: Тип изображения соответствует содержимому
- **WHEN** провайдер вернул изображение типа JPEG
- **THEN** результат содержит этот тип, а сохраняемый файл получает расширение по этому типу

#### Scenario: Конвертация не выполняется
- **WHEN** тип изображения отличается от ожидаемого
- **THEN** байты сохраняются как есть, без перекодирования и без новых зависимостей

### Requirement: Учёт стоимости
Провайдер ДОЛЖЕН (SHALL) возвращать стоимость вызова из поля `usage` провайдера, чтобы прогон можно было оценить по деньгам.

#### Scenario: Стоимость доступна в результате
- **WHEN** провайдер вернул ответ
- **THEN** результат содержит стоимость вызова, а при её отсутствии не выдумывается значение

### Requirement: Устойчивость и понятные отказы
Провайдер ДОЛЖЕН (SHALL) повторять временно неуспешные вызовы до трёх раз, не повторять постоянные ошибки, поднимать типизированные ошибки с понятным сообщением и не выполнять сетевой вызов при пустом ключе.

#### Scenario: Временный сбой повторяется
- **WHEN** вызов падает с сетевой ошибкой, 429 или 5xx
- **THEN** система повторяет попытку до трёх раз

#### Scenario: Постоянная ошибка не повторяется
- **WHEN** вызов отклонён с 400, 401, 403, 404 или 422
- **THEN** система поднимает постоянную ошибку после одного запроса

#### Scenario: Пустой ключ
- **WHEN** ключ RouterAI не задан
- **THEN** система поднимает постоянную ошибку с понятным сообщением и сетевой запрос не выполняется

#### Scenario: Ответ без изображения
- **WHEN** ответ не содержит изображения или содержит некорректный base64
- **THEN** система поднимает типизированную ошибку с понятным сообщением

### Requirement: Настраиваемость и mock-режим
Провайдер ДОЛЖЕН (SHALL) читать адрес, ключ и модель из настроек, а при пустом ключе ДОЛЖЕН (SHALL) использоваться mock-провайдер, не выполняющий сетевых вызовов.

#### Scenario: Модель и адрес берутся из настроек
- **WHEN** в настройках заданы другой адрес или другая модель
- **THEN** запрос уходит на этот адрес с этой моделью без изменений кода

#### Scenario: Mock без ключа
- **WHEN** ключ пуст
- **THEN** выбирается mock-провайдер, детерминированный по seed, и сетевых вызовов не происходит
