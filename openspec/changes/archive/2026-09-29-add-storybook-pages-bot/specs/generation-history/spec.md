## REMOVED Requirements

### Requirement: Содержимое записи о генерации
**Reason**: два сценария требования описаны через запись о видео и идентификатор запроса к видеопровайдеру, а видео больше не является частью продукта; оставшийся сценарий про сказку не покрывает новый состав записи.
**Migration**: заменено требованием «Запись о прогоне книжки» ниже и требованием «Содержимое записи о генерации» capability `storybook-bot-flow`.

## ADDED Requirements

### Requirement: Запись о прогоне книжки
Система ДОЛЖНА (SHALL) сохранять запись для каждого прогона, содержащую идентификатор пользователя, отметку времени, тип генерации, статус, путь к сохранённому фото, число страниц, полный текст сказки (страницы, склеенные в один абзац в порядке номеров) и каталог прогона, в котором лежат файлы иллюстраций. Каталог прогона ДОЛЖЕН (SHALL) оставаться техническим полем для разбора и не публиковаться в чате: он содержит персональные фото. Значение, которое не передано при обновлении записи, ДОЛЖНО (SHALL) сохраняться прежним, а не затираться.

#### Scenario: Запись о книжке сохранена
- **WHEN** прогон завершился успешно
- **THEN** система сохраняет запись с идентификатором пользователя, временем, типом «сказка», статусом успеха, числом страниц, полным текстом сказки и каталогом прогона

#### Scenario: Запись связана с фото
- **WHEN** принятое фото сохраняется и для него создаётся запись о прогоне
- **THEN** запись содержит путь к сохранённому файлу фото, по которому его можно переиспользовать и проверить

#### Scenario: Запись обновлена частичным результатом
- **WHEN** прогон завершился со статусом «требует проверки» или ошибкой
- **THEN** система обновляет статус своей записи, сохраняет текст сказки, число страниц, каталог прогона и техническую причину для разбора, а не ссылку на артефакт

#### Scenario: Прогон не начался из-за отказа по квоте
- **WHEN** прогон не был запущен, потому что квота пользователя израсходована
- **THEN** запись закрывается как не начавшаяся, с указанием причины отказа, и не остаётся в состоянии выполнения навсегда

#### Scenario: Сбой записи не отнимает ответ у пользователя
- **WHEN** база данных недоступна в момент записи результата
- **THEN** пользователь всё равно получает книжку, а сбой фиксируется в логе и не прерывает выдачу
