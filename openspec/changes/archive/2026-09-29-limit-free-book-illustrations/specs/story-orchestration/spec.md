## MODIFIED Requirements

### Requirement: Единое состояние прогона
Система ДОЛЖНА (SHALL) передавать между этапами единый объект `StoryState` с входными параметрами (`theme`, `age`, `moral`, `num_pages`, набор иллюстрируемых страниц), артефактами этапов (бриф, страницы, реестр сущностей, сцены, промпты изображений с номерами принадлежащих им страниц, путь и seed character sheet, пути и seed изображений), историей вердиктов, счётчиком ревизий, статусом и метриками этапов. Набор иллюстрируемых страниц ДОЛЖЕН (SHALL) материализовываться до первого этапа, который его читает, чтобы генератор изображений, проверка покрытия и промпт сценариста работали с одним и тем же набором. Если вызывающая сторона задала набор явно, он ДОЛЖЕН (SHALL) использоваться как есть; иначе набор ДОЛЖЕН (SHALL) вычисляться из бюджета иллюстраций и числа страниц.

#### Scenario: Состояние протаскивается через все этапы
- **WHEN** пайплайн выполняет любой этап
- **THEN** этап получает текущий `StoryState` и возвращает его с заполненными артефактами этого этапа

#### Scenario: Состояние сериализуемо без бинарных данных
- **WHEN** прогон завершён и состояние сохраняется
- **THEN** состояние сериализуется в JSON без бинарных данных, а изображения представлены путями и seed

#### Scenario: Набор известен до первого этапа
- **WHEN** начинается прогон
- **THEN** набор иллюстрируемых страниц уже заполнен в состоянии и не меняется на протяжении прогона

#### Scenario: Явно заданный набор не перетирается
- **WHEN** вызывающая сторона задала набор иллюстрируемых страниц до запуска прогона
- **THEN** прогон использует именно этот набор, а не вычисляет его заново

#### Scenario: Различение причин отсутствия картинки в артефактах
- **WHEN** прогон завершён, и у части страниц нет картинки
- **THEN** по сохранённому состоянию однозначно видно, какие страницы не иллюстрировались по замыслу, а какие из-за сбоя

### Requirement: Запуск из командной строки
Система ДОЛЖНА (SHALL) предоставлять запуск из командной строки с параметрами `theme`, `age`, `moral` и опциональным числом страниц, создающий каталог `output/{timestamp}/` с файлами иллюстрируемых страниц и файлом `story.json`, содержащим полное состояние прогона. Файлы создаются ДОЛЖНЫ (SHALL) для страниц из набора иллюстрируемых, а не обязательно для каждой страницы: при бюджете меньше числа страниц каталог содержит меньше файлов страниц. Каталог, заданный самим прогоном, ДОЛЖЕН (SHALL) не перетираться значением из настроек: оркестратор подставляет каталог из настроек только тогда, когда прогон не задал свой, иначе параллельные прогоны писали бы файлы в одно место.

#### Scenario: Каталог результата создаётся
- **WHEN** пользователь запускает CLI с темой, возрастом и моралью
- **THEN** создаётся каталог `output/{timestamp}/` с одним файлом на каждую иллюстрируемую страницу и файлом `story.json`

#### Scenario: Бюджет иллюстраций сокращает число файлов страниц
- **WHEN** бюджет иллюстраций меньше числа страниц
- **THEN** каталог содержит файлы только для страниц из набора иллюстрируемых, а `story.json` содержит этот набор

#### Scenario: Нулевой бюджет возвращает файлы всех страниц
- **WHEN** бюджет иллюстраций равен нулю
- **THEN** каталог содержит файл на каждую страницу, как до появления бюджета

#### Scenario: Число страниц по умолчанию
- **WHEN** число страниц не задано
- **THEN** используется значение по умолчанию — шесть страниц

#### Scenario: Некорректный возраст отклоняется
- **WHEN** значение возраста выходит за пределы, заданные настройками
- **THEN** CLI завершается понятной ошибкой, не начиная генерацию

#### Scenario: Некорректное число страниц отклоняется
- **WHEN** число страниц выходит за пределы, заданные настройками
- **THEN** CLI завершается понятной ошибкой, не начиная генерацию (защита от неограниченного расхода на изображения)

#### Scenario: Каталог прогона не перетирается
- **WHEN** прогон запущен с собственным каталогом вывода, отличным от каталога из настроек
- **THEN** оркестратор оставляет каталог прогона, и результаты пишутся в него, а не в каталог из настроек

### Requirement: Конфигурация пайплайна отдельно от бота
Система ДОЛЖНА (SHALL) использовать настройки, читаемые из окружения и `.env`, позволяющие задать параметры изображений, число страниц по умолчанию, диапазон числа страниц, бюджет иллюстрируемых страниц, лимит ревизий, диапазон возраста и каталог вывода, без требования токена бота MAX. Бюджет иллюстрируемых страниц ДОЛЖЕН (SHALL) быть неотрицательным и ДОЛЖЕН (SHALL) проверяться при загрузке настроек, то есть до первого платного вызова: значение `0` отключает ограничение и означает иллюстрирование всех страниц, а значение не меньше числа страниц схлопывается в иллюстрирование всех страниц.

#### Scenario: Запуск без токена бота
- **WHEN** токен бота MAX не задан
- **THEN** пайплайн запускается и работает, если заданы необходимые для него ключи или провайдеры замоканы

#### Scenario: Mock-режим без ключа изображений
- **WHEN** ключ генерации изображений пуст
- **THEN** используется mock-провайдер изображений, и реальные обращения к API изображений не выполняются

#### Scenario: Отсутствует ключ текстовой модели
- **WHEN** ключ текстовой модели не задан
- **THEN** пайплайн завершается понятной ошибкой до генерации, не выполняя бессмысленных обращений к API

#### Scenario: Отрицательный бюджет отклоняется
- **WHEN** бюджет иллюстрируемых страниц отрицателен
- **THEN** настройки не загружаются и выдаётся понятная ошибка, не доводя до пустого набора страниц и платных вызовов

#### Scenario: Нулевой бюджет отключает ограничение
- **WHEN** бюджет иллюстрируемых страниц равен нулю
- **THEN** иллюстрируются все страницы прогона
