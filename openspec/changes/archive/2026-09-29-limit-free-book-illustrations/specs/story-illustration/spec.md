## MODIFIED Requirements

### Requirement: Генерация PNG по странице
Система ДОЛЖНА (SHALL) сохранять по одному файлу на каждую иллюстрируемую страницу с именем вида `page_N.<расширение>`, где расширение определяется типом файла, полученным от провайдера (по умолчанию — `.png`), передавать провайдеру детерминированный seed, выведенный из номера страницы (для character sheet — собственное фиксированное значение), и записывать в состояние seed, если провайдер его вернул. Страницы вне набора иллюстрируемых ДОЛЖНЫ (SHALL) оставаться без файла и без вызова провайдера. Конвертация изображения ДОЛЖНА (SHALL) не выполняться: байты сохраняются как есть, потому что добавлять зависимости для перекодирования нельзя. Провайдер, не поддерживающий seed, возвращает `null`, и поле остаётся пустым: воспроизводимость не выдумывается.

#### Scenario: Файл на каждую страницу
- **WHEN** генерация изображений завершена успешно
- **THEN** для каждой страницы из набора иллюстрируемых существует файл с именем `page_N` и расширением по типу файла провайдера, а в состоянии сохранены путь и seed

#### Scenario: Страница вне набора не заказывается
- **WHEN** страница не входит в набор иллюстрируемых
- **THEN** вызов провайдера для неё не выполняется, файл не создаётся, а прогон не считается из-за этого неполным

#### Scenario: Seed сохраняется для воспроизводимости
- **WHEN** провайдер поддерживает seed и вернул его
- **THEN** значение seed сохраняется в состоянии прогона

#### Scenario: Разные страницы получают разные seed
- **WHEN** генерируются страницы 1 и 2
- **THEN** провайдеру передаются разные seed, выведенные из номеров страниц, а в mock-режиме файлы страниц не совпадают байт-в-байт

#### Scenario: Провайдер не поддерживает seed
- **WHEN** провайдер не возвращает seed
- **THEN** в состоянии сохраняется `null` без выдуманного значения

#### Scenario: Пропущенный PNG не даёт статуса `ok`
- **WHEN** для какой-то страницы из набора иллюстрируемых файл не записан (сбой генерации, потерянная сцена, номер вне диапазона)
- **THEN** прогон получает статус `needs_review`, а номер страницы фиксируется в ошибке метрики этапа

#### Scenario: Тип файла берётся из ответа провайдера
- **WHEN** провайдер вернул изображение типа JPEG, хотя запрос не задавал формат
- **THEN** файл страницы получает расширение по этому типу, а не `.png`, и байты сохраняются без перекодирования

#### Scenario: Файл листа называется по своему типу
- **WHEN** character sheet сохранён
- **THEN** его имя строится по типу файла, который вернул провайдер, а не по жёстко заданному расширению

## ADDED Requirements

### Requirement: Набор иллюстрируемых страниц
Система ДОЛЖНА (SHALL) определять набор иллюстрируемых страниц как подмножество номеров `1..num_pages` по бюджету иллюстраций, заданному настройкой. Набор ДОЛЖЕН (SHALL) быть непустым, не содержать повторов и выходить за пределы диапазона страниц. При бюджете, равном нулю, или не меньшем числа страниц, набор ДОЛЖЕН (SHALL) совпадать со всеми страницами — это отключение ограничения, сохраняющее прежнее поведение. При промежуточном бюджете набор ДОЛЖЕН (SHALL) распределять страницы равномерно по книжке и обязательно включать первую и последнюю страницы. Система ДОЛЖНА (SHALL) использовать один и тот же набор для выдачи картинок, проверки покрытия и текста сценарика, чтобы прогон не мог заказать, проверить и рассказать о разных наборах.

#### Scenario: Набор по умолчанию для шести страниц
- **WHEN** число страниц равно 6, а бюджет иллюстраций равен 3
- **THEN** иллюстрируются страницы 1, 4 и 6

#### Scenario: Нулевой бюджет отключает ограничение
- **WHEN** бюджет иллюстраций равен нулю
- **THEN** иллюстрируются все страницы, а проверка покрытия ожидает файлы для каждого номера от 1 до числа страниц

#### Scenario: Бюджет не меньше числа страниц
- **WHEN** бюджет иллюстраций не меньше числа страниц
- **THEN** иллюстрируются все страницы, ограничение не даёт пустого набора

#### Scenario: Ограничение не выходит за диапазон
- **WHEN** набор иллюстрируемых страниц нормализуется, и в него попали номера вне диапазона `1..num_pages`, повторы или ничего
- **THEN** нормализованный набор сводится к корректному непустому подмножеству страниц без повторов, и прогон продолжает работу

#### Scenario: Нормализация применяется и к явно заданному набору
- **WHEN** вызывающая сторона задала набор иллюстрируемых страниц явно, и он некорректен
- **THEN** набор нормализуется тем же правилом, что и вычисленный, поэтому прогон не может завершиться пустым или выходящим за диапазон множеством страниц

#### Scenario: Крайние страницы входят в набор
- **WHEN** бюджет меньше числа страниц, но набор непуст
- **THEN** набор содержит первую и последнюю страницы

#### Scenario: Набор один на весь прогон
- **WHEN** прогон выполняется с ограниченным бюджетом
- **THEN** генератор изображений, проверка покрытия и промпт сценариста работают с одним и тем же набором номеров

### Requirement: Промпты изображений с номерами страниц
Система ДОЛЖНА (SHALL) сохранять в состояние промпты изображений вместе с номером страницы, которой они принадлежат, и ДОЛЖНА (SHALL) сохранять промпты только для страниц из набора иллюстрируемых. Привязка промпта к номеру страницы ДОЛЖНА (SHALL) позволять отличить промпт нарисованной страницы от промпта страницы, которая не рисовалась, без обращения к порядку элементов в списке.

#### Scenario: Промпты только для иллюстрируемых страниц
- **WHEN** бюджет ограничен и отрисована часть страниц
- **THEN** в состоянии сохранены промпты только этих страниц, и ни один промпт страницы вне набора не сохранён

#### Scenario: Промпт принадлежит своей странице
- **WHEN** сохранён промпт изображения
- **THEN** он хранится вместе с номером страницы, поэтому принадлежность промпта читается напрямую, а не по порядку в списке

#### Scenario: Сцены вне набора промпта не получают
- **WHEN** сцена соответствует странице вне набора иллюстрируемых
- **THEN** промпт для неё не собирается вовсе, а провайдер для неё не вызывается

### Requirement: Отсутствие картинки по замыслу не считается сбоем
Система ДОЛЖНА (SHALL) отличать отсутствие картинки у страницы вне набора иллюстрируемых от сбоя генерации у страницы внутри набора. Отсутствие картинки по замыслу ДОЛЖНО (SHALL) оставлять прогон в статусе `ok`, не порождать ошибку метрики этапа и не выдаваться как частичный результат. Сбой генерации у иллюстрируемой страницы ДОЛЖЕН (SHALL) сохранять прежнее поведение: статус `needs_review`, запись причины в метрику этапа и продолжение генерации остальных страниц.

#### Scenario: Страница вне набора не порождает needs_review
- **WHEN** у части страниц нет картинки, и все эти страницы вне набора иллюстрируемых
- **THEN** прогон получает статус `ok`, а в метрике этапа иллюстрирования нет ошибки

#### Scenario: Сбой на иллюстрируемой странице остаётся сбоем
- **WHEN** генерация картинки для страницы из набора иллюстрируемых не удалась после повторов
- **THEN** прогон получает статус `needs_review`, номер страницы попадает в ошибку метрики этапа, а остальные страницы дорисовываются

#### Scenario: Разные причины видны в состоянии прогона
- **WHEN** прогон завершён и в нём есть страницы без картинки
- **THEN** по сохранённому состоянию прогона можно однозначно определить, какие страницы не иллюстрировались по замыслу, а какие не иллюстрировались из-за сбоя
