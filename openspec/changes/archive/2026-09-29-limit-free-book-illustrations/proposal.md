## Why

Бесплатная генерация сейчас рисует иллюстрацию к каждой странице: при
`STORY_DEFAULT_PAGES = 6` это 1 лист персонажей + 6 картинок, то есть **7
платных генераций изображений** на одного нового пользователя, пришедшего по
рекламе или по рекомендации. Текстовые вызовы DeepSeek на этом фоне
сопоставимо дешевы, и основная стоимость продукта — именно иллюстрации.

Бесплатная книжка должна оставаться пригодной для ребёнка 3–6 лет, но не
обязана иллюстрировать каждую страницу. Ограничение иллюстраций уменьшает
стоимость входа примерно на 43 % без сокращения объёма текста — длинная
сказка с тремя сильными картинками полезнее родителю, чем короткая с шестью
слабыми.

Ограничение нельзя ввести как «перестать рисовать часть страниц» поверх
текущего кода. Сегодня ожидаемое покрытие иллюстраций выводится из
`num_pages`, и отсутствие картинки автоматически означает `needs_review`,
а значит — нерасходуемую квоту, предложение переделать книжку и сообщение
«картинку отрисовать не вышло». Бесплатная генерация стала бы бесконечной и
вругала бы пользователя о несуществующем сбое. Поэтому пропуск по замыслу и
пропуск по сбою должны стать разными сущностями, а не разными оттенками
одного и того же статуса.

## What Changes

- В пайплайн вводится понятие **набора иллюстрируемых страниц** — подмножества
  `1..num_pages`, для которого заказываются картинки. Число страниц текста и
  число картинок перестают быть одной величиной.
- Новая настройка `STORY_ILLUSTRATED_PAGES` (по умолчанию `3`) задаёт бюджет
  иллюстраций на прогон; `0` означает «без ограничения, рисуем все
  страницы» и сохраняет прежнее поведение CLI для приёмки и отладки.
- Набор страниц вычисляется по правилу «обложка, пред-финал, финал»
  (`1, N-2, N`), что при `num_pages = 6` даёт `1, 4, 6`: ребёнок сразу видит
  героя, середина и финал — визуальные вершины. Правило устойчиво к людому
  `num_pages` и корректно деградирует на малых значениях.
- Сценарист **знает**, какие страницы будут проиллюстрированы, и строит дугу
  так, чтобы именно они были визуальными вершинами. Требование промпта
  «каждая страница должна быть иллюстрируема» заменяется: иллюстрируемыми
  объявляются только отмеченные страницы, остальные — связки.- Проверка покрытия иллюстраций сверяет записанные файлы с **набором
  иллюстрируемых страниц**, а не с `1..num_pages`. Пропуск по замыслу больше
  не переводит прогон в `needs_review`.
- Сбой генерации картинки для иллюстрируемой страницы по-прежнему даёт
  `needs_review`, частичный результат, нерасходуемую квоту и одно
  предложение переделать книжку. Семантика отказа не меняется — меняется
  только множество страниц, с которым она сверяется.
- Бесплатная книжка с тремя картинками считается **доставленной целиком**:
  квота расходуется, статус записи — успех.
- Бот один раз, перед книжкой, объясняет, что в бесплатной книжке картинки
  есть не к каждой странице, и называет номера страниц с картинками.
  Формулировка собирается из фактического набора, а не хранится константой.
- Страницы без картинки **по замыслу** приходят обычным текстом, без
  извинения за «неотрисованную картинку». Извинение остаётся только для
  реальных сбоев генерации и неотправленных вложений.
- Промпты изображений сохраняются вместе с номером страницы и только для
  иллюстрируемых страниц, чтобы разбор прогона по `story.json` видел, какой
  промпт к какой нарисованной странице относится.
- Итог книжки с замечаниями к тексту больше не утверждает, что иллюстрации
  есть у всех страниц: при ограниченном наборе он говорит, что книжка
  собрана целиком по заданному набору.
- Состояние прогона и CLI-документация приводятся в соответствие: набор
  иллюстрируемых страниц назван входным параметром прогона, бюджет — среди
  настроек пайплайна, каталог результата содержит файлы иллюстрируемых
  страниц.
- Лист персонажей сохраняется: он генерируется первым и остаётся единым
  якорем внешности для всех иллюстрируемых страниц.

Итоговая стоимость бесплатной генерации: **7 → 4** платных вызова изображений
(−43 %) плюс текстовые вызовы без изменений.

## Capabilities

### New Capabilities

Нет. Изменение укладывается в существующие capability: новое поведение —
это ограничение и разделение ответственности внутри уже описанных
иллюстрирования, текста, квоты и выдачи.

### Modified Capabilities

- `story-illustration`: покрытие страниц сверяется с набором
  иллюстрируемых страниц, а не с `1..num_pages`; пропуск по замыслу не даёт
  `needs_review`, а сбой по иллюстрируемой странице даёт; набор страниц
  задаётся бюджетом из настроек.
- `story-text-generation`: сценаристу сообщается набор иллюстрируемых
  страниц, требование «каждая страница иллюстрируема» заменяется на
  требование иллюстрируемости только отмеченных страниц.
- `usage-limits`: бесплатная генерация — книжка с ограниченным числом
  картинок; она считается доставленной целиком и расходует квоту, поскольку
  отсутствие картинок у части страниц заложено замыслом, а не сбоем.
- `bot-conversation`: перед книжкой отправляется одно объяснение с номерами
  страниц, имеющих картинку; страницы без картинки по замыслу отправляются
  текстом без извинения.
- `storybook-bot-flow`: перечень «страниц без иллюстраций» считается по
  набору иллюстрируемых страниц, поэтому книжка с ограниченным числом
  картинок не считается частичным результатом; требование о цепочке
  референсов уточняет, что лист персонажей строится независимо от бюджета.
- `story-orchestration`: набор иллюстрируемых страниц становится входным
  параметром прогона, бюджет — настройкой пайплайна, каталог результата
  содержит файлы иллюстрируемых страниц, а не обязательно всех.

## Impact

- **Настройки**: `app/story_pipeline/settings.py` (`StorySettings`),
  `.env.example` и таблица переменных в `README.md` — новая переменная
  `STORY_ILLUSTRATED_PAGES`. Новых зависимостей нет.
- **Состояние прогона**: `app/story_pipeline/models.py` — новое поле с
  набором иллюстрируемых страниц и привязкой промптов изображений к номерам
  страниц; попадает в `story.json`, что позволяет разбору отличить «нет
  картинки по замыслу» от сбоя.
- **Пайплайн**: `app/story_pipeline/stages/screenwriter.py` и
  `app/story_pipeline/prompts.py` — набор страниц в промпте сценариста и
  его починочном запросе; `app/story_pipeline/stages/image_generator.py` —
  выбор страниц для генерации и новое множество ожидаемого покрытия.
- **Бот**: `app/bot/runner.py` — расчёт пропущенных страниц по набору,
  новое сообщение-объяснение и отправка страниц по замыслу без извинения.
- **Обратная совместимость**: `STORY_ILLUSTRATED_PAGES=0` возвращает прежнее
  поведение целиком — все страницы иллюстрируются, проверка покрытия
  сравнивает с `1..num_pages`. Записи о старых успешных книжках в квоте
  продолжают засчитываться без изменений.
- **Тесты**: `tests/story_pipeline/` и `tests/`. Путь «страница по замыслу
  без картинки» важнее happy path: он не должен давать `needs_review`, не
  должен расходовать квоту и не должен извиняться перед пользователем.
